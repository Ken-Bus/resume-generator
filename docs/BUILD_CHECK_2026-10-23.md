# Build check: why the Console one-liner failed, and the replacement

**Reported:** `fetch('/.netlify/functions/polish-resume',{method:'POST',body:'{}'}).then(r=>r.json()).then(console.log)` showed `401 Unauthorized` and `TypeError: r.json is not a function`.

1. **The 401 is expected application behaviour, not Netlify protection.** A POST with no access code is answered `401` by `polish-resume` itself (before any database, licence or AI step). Netlify access protection would answer with its own HTML page, not our JSON; the 401 body here is our JSON with `guard`. Chrome lists any 4xx in red in the Console even when it is correct.
2. **The reply is valid JSON.** `Content-Type: application/json`, body `{"error":"...","guard":{"version":"entry-scope-withhold-4","withholds":true,"deploy":...}}`. Replayed in Chromium against the real handler output, the exact command prints it (test `tests/ui/live-replay.test.js`). `fetch` always resolves to a Response, which always has `.json()`, so the TypeError cannot come from the server's reply: it means `r` was not a Response at that point, for example the command was chained after `.then(r=>r.status)` (SETUP.md has such one-liners just above this one, and a status is a number) or a different snippet ran. So: **not a server defect**, but a fragile recipe.
3. **Safe without a licence?** Yes. The stamp is only a version label and the deploy id; it needs no code, reserves nothing, calls no AI, charges nothing.
4. **Simplest method, no Console:** open `https://<branch-site>/.netlify/functions/polish-resume` in a browser tab. A plain visit is a GET; it now answers `405` with readable JSON `{"error":"Method Not Allowed","guard":{"version":"entry-scope-withhold-4",...}}` (same for `tailor-resume` and `parse-resume`). Before this change it said only `Method Not Allowed`, so this is the fix (small, `netlify/functions/_lib/release.js`). Unauthorised requests stay blocked: POSTs without or with a bad code still return 401/400/403, nothing is served on GET, and tests assert no reservation or AI call happens.
5. **Mismatched deployments.** A Netlify deploy ships the page and the functions together, from the same `resume-core.js`, so a mismatch occurs only (a) in a browser tab opened before a deploy (old page, new server) or (b) if an old deploy is still being served (old page AND old functions). (a) is now caught by the server: the page sends `clientGuard` with Analyze, Polish and Tailor; a different version is refused with `409` ("This page is out of date. Please refresh...") before any reservation, AI call or charge. (b) is detected by the free address check above (a bare "Method Not Allowed" without `guard`, or `ResumeCore.GUARD_VERSION` undefined). There is no case where a new page talks to an old server within one deploy; no per-request preflight was added for that reason.
